# Codex レビュー: スマホ中央フォーカス方式 + タップ星生成修正（2026-07-27）

- 対象コミット: 92dc3bb（工程1）
- 対象ファイル: `drafts/mock-p2d2-oilmoon.html` / `drafts/mock-p2e2-impasto.html`
- 実行方法: `codex exec --sandbox read-only`（読み取り専用）

## 背景（バグ報告 → 仕様変更）

旧仕様「下スクロールで入場した要素に 1.1 秒の通過グロー」に対し、スマホで
①複数同時にアクティブになる ②画面中央の要素がアクティブにならない ③タッチしてもアクティブにならない、
さらに LINE 内ブラウザで ④タップしても星（黄色い丸）が生まれない、との報告。

## 新仕様（今回実装）

1. **中央フォーカス**: 基準線（画面上から 45%）に最も近い 1 要素だけを常時 `.mfocus`。
   上下どちらのスクロールでも入れ替わり、同時に複数は光らない。基準線から `innerHeight×0.3` 超は非アクティブ
2. **タップで即アクティブ**: 350ms 以内・移動 12px 以内のタップで `.mfocus` を付与し、次のスクロールまで保持
3. **星の生成**: タッチ端末は `touchend` のタップ判定で生成（WKWebView=LINE 内ブラウザで window に click が
   届かない問題への対処）。スワイプ・スクロールでは生成しない。PC は従来どおり click（a/button は除外）

## 事前検証（puppeteer タッチエミュレーション、6 項目）

初期表示は非アクティブ / 下スクロールで 1 件のみ / 入れ替わり / 上スクロールでもアクティブ /
タップした要素が即アクティブ / 連続スクロール 12 回で同時アクティブ最大 1 — すべてパス。
（初回実装で「閾値 50% が緩く見切れカードが光る」「合成 click がタップ選択を上書き」の 2 件を検出し、修正後に再検証済み）

## 判定結果

- **重大: なし / 中程度: なし / 軽微: 1 件**

| # | 区分 | 指摘 | 対応 |
|---|---|---|---|
| 1 | 軽微 | CSS コメントが旧仕様「通過グロー」のまま（D2:346 / E2:358）。挙動バグではない | **工程3 で修正済み**（中央フォーカスの説明に更新） |

Codex の確認内容（要約）: `.mfocus` は `setActive()` が前の active を必ず外すため同時複数化しない。
タップ hold は次の scroll/resize で解除され、rAF の pending も破綻なし。PC の星生成は `isTouch` で
touch 経路を無効化し合成 click との二重発火なし。a/button 除外は操作ボタンでの誤生成防止として妥当。
`prefers-reduced-motion` 時は中央フォーカス処理自体が起動せず従来挙動を維持。
